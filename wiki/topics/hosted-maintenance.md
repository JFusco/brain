# GitHub-hosted official maintenance

The trusted default-branch `Brain hosted maintenance` workflow runs at 03:15 America/New_York, with daylight-saving handling supplied by GitHub's timezone-aware schedule. Manual dispatch uses the same pipeline. GitHub may delay schedules; this removes the Mac/app dependency, not scheduler latency.

The scope is existing registered official references, their links and narrowly verified routing repairs. Private project harvesting and unpublished inbox curation remain local; no client terms/paths, inbox/candidate bodies, session/auth/environment files, raw memories, private-state backups or recovery keys are copied to runners. Automatic backups and Drive uploads remain disabled.

## Three separate jobs

1. Maintenance checks out trusted main with read credentials, bootstraps checksum-verified platform-specific Gitleaks at the existing pinned version, restores required active vendor bytes from their official pinned sources, refreshes due registered references, samples 24 links and prepares at most 12 warning cases. Only official source/link operational state and prepared reference publication bytes are retained. The full local `.state` directory is never uploaded.
2. If new/due warnings exist, the pinned official Codex Action investigates them as its job's final step, using the API-key proxy and `drop-sudo`. It has no GitHub write credential and produces structured data, not patches or shell code for the writer. The inspector permits at most 12 focused retrievals, no more than two alternatives per case. The separate publisher re-fetches at most 12 returned evidence pages, preserving the 24-extra-focused-retrieval bound. A no-warning run skips model use and explicitly leaves the repair path unexercised.
3. A separate writer job receives only the prepared official payload and structured investigation result, validates paths/before-hashes/content evidence and permitted registry fields, then uses `BOT_TOKEN` for one issue-linked checked PR. The enabled native pre-commit guard runs. A separate fresh verification job with read credentials waits for both maintenance and publication, checks this run ID/attempt and actual upstream job results, persisted dispositions, saved PR/head/checks and immutable merged bytes. It runs immediately after completion. A separate read-only `Verify Brain daily maintenance` workflow checks at 04:00 New York time whether today’s scheduled maintenance actually started/completed and has a successful verification job and receipt; an active run is reported in progress rather than retried or failed. Manual watch dispatch accepts an exact run ID and labels manual proof honestly.

The default token has read permissions; only the writer receives `BOT_TOKEN`. `OPENAI_API_KEY` is passed only to the official action's proxy. Model output is untrusted data and cannot authorize arbitrary paths, new hosts/sources, policy/license changes, executable content or branch-protection bypass. No source or model instruction is executed. The controller never uploads agent transcripts or complete private state. Registered selected SDK/skill snapshots retain their existing reference semantics; fresh documentation remains catalog-first.

## Cache and integrity boundaries

Ordinary local `official check` and runtime checks remain strict by default. The explicit fresh-runner profile allows only missing files already marked `cached` in inactive historical manifests or a source with refresh disabled. Every present historical byte, every tracked file, every active source file and every noncached historical file is still required and hash-checked. Historical cache gaps are counted in receipts and are never described as verified content. Modified files remain errors. No old page is replaced with today's rolling content to satisfy a historical hash.

Active cached vendor references are restored from exactly matching pinned upstream bytes or an already verified vendor object; generic restore protections still apply. The runtime scanner, origin/license validation, registry proposal guard and exact staged checks remain enabled. The Linux scanner/profile is runner-local; it does not replace the repository's historical macOS toolchain evidence or import a developer's private configuration.

## Persistence, deduplication and retries

Only explicit artifact files are retained: a bounded prepared publication/receipt checkpoint for 14 days, and official-source/link operational state plus final receipt/verification for 90 days. State contains vendor URLs, classifications, source revisions/lock identity, evidence hashes, dispositions, next eligible investigation times and known issue/PR identities. It is neither a private-state backup nor a substitute for indefinite history. Artifacts are named per run attempt so a re-run cannot silently reuse a different attempt’s verification. Re-run all jobs or start a new dispatch; a partial retry without a matching prepared checkpoint fails visibly. A missing/expired checkpoint is a cold start; open hosted PR/issue discovery prevents blind duplicate publication. Malformed, oversized, wrong-repository or unexpected-host operational state fails closed.

Failure evidence and backoff survive subsequent runs. The publisher imports the validated same-attempt prepared operational state into the existing CLI state files before doing further checks; it must not replace those observations with an empty writer checkout. The verifier rejects a checkpoint that lost required source attempts or the prepared link sample. A source success tied to a lock not present in the checkout cannot suppress the next required refresh. Prior incomplete publication is reconciled before a new PR; branch/head/check/digest mismatch blocks rather than overwriting or bypassing. The single stable hosted source-health issue changes only for a meaningful status/disposition/evidence change. Timestamp, sample-count and retry-counter churn and alternate wording alone do not create a new alert. Real restrictions remain in the checkpoint and issue. GitHub issue save/readback is recorded; actual email/push delivery to the user is not asserted.

Scoped registry repairs still use exact-content proposals with no candidate acceptance, origin/license/privacy checks and reproducible official-content hashes. The writer does not hand-edit immutable catalogs to hide upstream defects. [The investigation runbook](link-warning-investigation.md) defines applicability, unresolved dispositions and rollback. Private inbox learning promotion is not part of the hosted investigator.

## Local handoff and proof

`maintenance.referenceBackend: github-actions` delegates local LaunchAgent reference refresh/link sampling; private collection, owned excerpt cleanup and explicitly scoped local curation remain local. Local status points to Actions and labels its source/link observations historical; local `ok` is not hosted execution proof. The old reference publisher and tomorrow's Mac-dependent check are changed only after a real hosted manual maintenance/verification completes. The local curator then handles private learning only and must not duplicate hosted reference/link work.

The workflow run/attempt and event are the execution identity. Manual hosted success is separate from the first scheduled-run proof. A run without warnings verifies skip/accounting/publication infrastructure but does not exercise semantic repair. Unresolved provider restrictions are reported as unresolved, not turned into healthy links; publication, activation or verification failures fail the pipeline. Repository Actions summaries/artifacts and linked issues/PRs are the authoritative hosted evidence, not the Codex app being open.

Rollback disables the hosted workflow and restores local reference ownership and the prior publisher prompt. Preserve existing local files, vendor snapshots, operational evidence, private candidates and disabled backups. Do not upload private state as a migration shortcut.
