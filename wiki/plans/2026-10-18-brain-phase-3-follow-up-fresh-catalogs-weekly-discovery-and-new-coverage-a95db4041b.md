# Brain phase 3 follow-up — fresh catalogs, weekly discovery, and new coverage

## Context

Brain is the central place for project learnings, official documentation and official skills and agents. It should stay simple, and it should keep up with stacks that change often. After phase 3 ([JFusco/brain#57](https://github.com/JFusco/brain/pull/57), merged 2026-10-18 21:56 UTC), four problems remain:

1. **The weekly issue would sit open.** Rolling catalog drift (vercel-docs, contentstack-docs) would keep it open most weeks.
2. **Nothing discovers new official sources.** New skills repos, MCP servers and docs indexes go unnoticed. Joe wants this checked more often than monthly.
3. **Coverage gaps.**
   - Not registered at all: TypeScript, accessibility (WCAG 2.2 and WAI-ARIA), and Optimizely PaaS (CMS 13 .NET).
   - Pointer or skills only, no docs catalog: SitecoreAI docs, Sitecore on-prem (XP 10.4) docs, and Contentful docs.
   - Next.js, React, Tailwind and Optimizely SaaS are already catalogued.
4. **No way to refresh from the cloud.** This cloud sandbox can't reach vendor sites, so registrations and catalog refreshes have to run somewhere with network access.

**Joe's decisions (2026-10-18):**
- Drift never opens the issue.
- Discovery runs weekly.
- A small branch sync workflow lets any agent refresh and verify catalogs without the Mac.
- New domains `typescript`, `accessibility` and `cms/optimizely-paas`.
- Detect-and-explain for Mac leftovers.
- No size early warning; start link state fresh; no skill-change alerts.

**Delivery: two PRs in sequence on the designated branch `claude/magical-einstein-kdv7nw`.** The branch restarts from `main` after each merge, and both PRs stop for Joe's review.
- **PR A:** the mechanics. It must merge first, because a workflow can only be dispatched once it's on `main`.
- **PR B:** the registrations, with catalogs generated by PR A's workflow.

First, unsubscribe from #57. The 08:30 UTC check-in on 10-19 stays: it confirms the old hosted schedule didn't fire and looks at the first weekly run.

## PR A — keep catalogs fresh and look for new sources weekly

Create one issue (`enhancement`) first.

1. **`scripts/hosted/weekly.mjs`: drift out of the issue.**
   - Remove `changes` from the fingerprint and from the close condition.
   - List drift under "Routine catalog drift (informational; never opens this issue)" and always in the step summary. The close comment names the drifting sources.
   - Expected Outcome points to the weekly catalog refresh.
2. **New `.github/workflows/brain-sync.yml` ("Brain catalog sync").**
   - **Trigger:** `workflow_dispatch` only, with optional input `sources` (space-separated IDs; empty means all).
   - **Guard:** repo JFusco/brain, and a branch ref that isn't `main`.
   - **Permissions:** `contents: write`, using `GITHUB_TOKEN`; no secrets.
   - **Steps:**
     1. checkout and Node 24.14.0;
     2. `node scripts/hosted/setup.mjs`;
     3. `official sync $SOURCES`, with the JSON result written to the step summary;
     4. `check`, which must pass;
     5. set `core.hooksPath .githooks` and `WIKI_HOME`;
     6. stage only `official/catalogs/*.json`, `official/sources.lock.json` and `knowledge/**/INDEX.md`, failing on any other staged path;
     7. commit `chore(official): refresh catalogs` as github-actions[bot] (the pre-commit guard runs) and push to the same branch.
   - **Result:** the job fails if any source failed, after committing the sources that succeeded.
   - **PRs:** an agent opens the PR after the push, so the wiki check runs on the head.
3. **`scripts/lib/official.mjs`: leftovers message.** The unexpected-files message names the top-level leftover paths and the `rm -rf` command. It stays a warning in full mode and an issue in staged mode.
4. **Docs.**
   - **`AGENTS.md` → "Official references and maintenance"** gets two rules.
     - **Weekly catalog refresh:** run `official sync` locally, or dispatch Brain catalog sync on a fresh branch. If only catalogs, the lock and hubs changed, open a catalog-refresh PR, which auto-merges under step 7. Otherwise report.
     - **Weekly coverage review:** check the README watch list for new official docs indexes, skills or agent repos, and MCP servers in each domain. Open a registration PR for each finding, verified with Brain catalog sync, and stop for review. Never invent or guess a source.
   - **README.**
     - **Maintenance:** describe the sync workflow and say that drift never opens the issue.
     - **New "Coverage watch list" table** (per domain, the vendor's official places):
       - nextjs.org and vercel/vercel-labs;
       - react.dev;
       - typescriptlang.org and microsoft/TypeScript-Website;
       - tailwindcss.com and tailwindlabs;
       - w3.org/WAI and w3c;
       - vercel.com;
       - docs.optimizely.com, docs.developers.optimizely.com and episerver;
       - contentstack.com and contentstack;
       - doc.sitecore.com and Sitecore;
       - contentful.com/developers/docs and contentful.
5. **Wiki:** archive this plan, add a dated journal entry, add a bullet to automatic-knowledge-maintenance's current flow, then run `build-graph` and `check`.
6. **PR text:** the curator prompt addition, which covers the weekly refresh and the weekly coverage review.
